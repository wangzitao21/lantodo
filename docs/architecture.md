# LanTodo 设计说明

## 目标和信任边界

所有正常操作先写本地，不等待网络。双方都是可独立工作的客户端；为建立点对点连接，每个进程都暂时监听 TCP，但没有固定主设备；可选 NAS 作为常在线副本。没有注册、遥测和自动更新联网请求。

威胁模型覆盖：同一 Wi-Fi 上未授权设备、伪造发现广播、主动冒充某台设备、传输中断和重放旧记录。已授权设备被视为允许读写所属空间的资料库；不防御已授权设备或当前 OS 用户主动破坏数据。内容哈希是完整性标识，不是来源的数字签名。

## 因果版本图

每条待办用随机 128 位 UUID 标识。一次修改生成一个不可变 `Revision`：

```text
revision.id = SHA256(canonical JSON(body))
body = { schema, todoId, actor, deviceName, nonce, createdUtc, parents[], data }
data = { title, notes, date?, time?, completed, deleted, attachments? }
```

`parents` 是编辑者明确看到并决定取代的所有头版本。`createdUtc` 仅展示，既不决定覆盖也不决定同步方向；`nonce` 避免相同输入被误当成同一操作。日期和时间是用户选择的日历日期与当地墙上时间，第一版不实现时区转换或提醒通知。

核心不变量：

1. 同一 revision ID 对应相同内容，收到记录必须重新计算哈希。
2. 父版本存在且属于同一个待办。缺失父版本、跨待办引用、环、无效 schema 或字段格式全部拒绝。
3. 头版本是没有被已知子版本引用的版本。只有一个头时展示其内容；存在多个头时显示冲突，不把排序中的第一个头当成胜者。
4. 同步合并是不可变版本集合的并集，满足幂等、交换和结合的效果；导入先拓扑排序，持久化父版本后再持久化子版本。
5. 手工解决冲突创建一个以所有待决定头为父节点的新版本。旧版本永久留在历史中。如果两边又分别解决冲突，新决定也会成为并发分支。

示例：

```text
初始 R0
    ├── R1：电脑改为周四
    └── R2：手机改为周六

R1 和 R2 同为头 → 冲突
R3 的 parents=[R1,R2]，用户决定周日 → 一个新头
```

删除是 `deleted=true` 的普通版本，仍保留标题、备注和日期等内容。删除与未修改旧版本合并后只有删除头；删除与离线新修改合并后有两个头，必须用户决定。不存在按时间戳覆盖或整库替换。

第一版保守地在整条待办上判断并发。字段级合并属于后续优化，不能以减少提示为由丢弃分支。

编辑器传入打开时的 `expectedHeads`。保存时在本地写锁内重新比较；出现差异则抛出 `StaleEditException`，输入保持在编辑框，不生成覆盖版本。用户可以复制当前输入，重新打开最新待办并确认后保存。

## 本地存储与故障行为

Windows 和 Android 共用 SQLite 后端，业务及同步依赖 `ITodoStore`；持久化接口为 `IProfileDatabase`。结构和稳定性约定见 [数据库接口 v1](database-v1.md)。因果版本、哈希、删除和冲突规则保持不变，不同步数据库文件。

单次保存、一个导入批次或一次批量删除在 SQLite 事务内提交，提交后才更新内存头索引并发出变更通知。失败整体回滚，内存不会先于磁盘。同步会话跨多个批次，已提交批次保留，重试按版本 ID 去重。

启动检查数据库应用标识、结构版本、SQLite quick_check、记录内容哈希和完整父图。遇到未来版本、损坏或缺父记录失败关闭。头索引仍在启动时由完整历史重建，多年大数据规模尚需基准测试。

数据库使用 `journal_mode=DELETE`、`synchronous=FULL`，禁用连接池。纯文字资料的空闲目录只有数据库；v1.0.1 的原件存储于旁边的 `attachments/`，事务进行中或崩溃恢复前可能出现 `-journal`，不为减少临时文件而关闭事务日志。参考 [SQLite 临时文件](https://www.sqlite.org/tempfiles.html) 和 [PRAGMA](https://www.sqlite.org/pragma.html)。Windows 使用跨进程命名互斥量，专用线程拥有和释放，以适应异步调用切换线程；Android 使用应用私有目录和进程内唯一运行时。

旧版转换先在临时 SQLite 中校验版本图、身份与元数据，关闭重开验证后才发布最终文件，并删除已导入的旧文件。旧自动备份字节以 `legacy-backup/文件名` 元数据存储。显式导出继续使用数据专用 ZIP 格式 v1，恢复只合并历史，不复制身份。

不自动删除墓碑、旧版本或归档备份。应用不再自动生成每日独立 ZIP；同一数据库里的历史无法替代独立磁盘备份。已做事务故障注入，尚未进行真实硬件断电实验。

## 发现和传输

局域网发现使用 IPv4 UDP `42852`，组播组 `239.255.42.51`（TTL=1），同时向广播地址和活动接口的子网广播地址发送。约每 30 秒公告 `{protocol, deviceId, port, generation}`，本地修改会立即公告新的随机变化标记，不公告设备名或待办内容。接收端只使用数据包来源地址，不接受广播中任意指定的地址。

发现缓存限制 128 台，条目 100 秒过期；广播不构成授权。接口加入在周期内重试，可适应 Wi-Fi / DHCP 改变；需要在真实多网卡、VPN 和路由器环境检验。固定 TCP 端口为 `42851`；测试可使用系统动态端口。

每台设备持有 RSA-3072 自签名证书，设备 ID 为整个证书 DER 的 SHA-256。TLS 1.2/1.3 双向出示证书。连接发起方固定校验期望设备 ID，避免假广播把它引导到攻击者。Windows Schannel 需要用户 CNG 密钥容器；Android 使用临时加载密钥。

监听端允许未知证书完成 TLS，仅用于兑换邀请或提交同根的签名成员证明。每条数据请求仍检查当前权限；未完成空间握手的旧版数据请求被拒绝。

`lantodo2:<base64 JSON>` 邀请包含空间根哈希、邀请者证书指纹、256 位随机秘密、名称、可达地址提示和到期时间。邀请只供一个证书身份兑换，五分钟有效，秘密不写入历史；相同证书可以重试确认。邀请者使用自己的私钥签署新成员的证书，接收者验证所有成员事件和邀请中固定的空间根，确认自己已获成员身份后才采用该空间授权；加入过程只准备独立连接配置，PeerNode 共用同一 TodoStore。

成员因果日志包含 create / add / remove，事件 ID 是规范 JSON 的 SHA-256，RSA SHA-256 签名覆盖完整事件体。根事件固定空间身份，每个后续操作必须由其因果历史中的有效成员签发。并发移除优先；移除后重新加入的授权必须包含已知移除历史。并发被移除的邀请者不能通过离线新增分支保留新成员权限，其无效邀请后代也不能移除已有成员。当前限制累计 64 个设备身份、512 个事件，不删除安全记录来腾出空间。

旧版资料在明确升级后建立新空间，旧配对不会自动转换为第三方授权。加入另一空间明确提示同步本机全部内容，并可通过同时加入多个空间的设备接力传递。每台设备的密钥独立保留，无共享永久管理员密码；空间内成员拥有相同的邀请与移除权限。

## 同步协议 v1

长度前缀大端 `uint32` + UTF-8 JSON，最大 2 MiB；每次 I/O 超时 20 秒，连接和 TLS 握手独立限时。输入最多 32 个并行连接。未知 schema 和协议版本拒绝，不做推测性降级。

1. `inventory(offset)`：接收端为本次连接拍下拓扑有序的不可变版本快照，每页 256 个 ID。
2. 发起方比对自己的 ID 集合，以最多 4 条一批 `get(ids)` 拉取缺失记录，校验并保存。
3. 发起方 `put(revisions)` 推送对方清单中没有的本地记录，同样按拓扑顺序；接收端保存后回复 `saved`。
4. v1.0.1 协商附件能力后，先交换附件失效引用，再按清单和回收站引用交换有效的缺失原件；通过 256 KiB 分块续传与 SHA-256 校验。双方 `done` 确认本轮结束。本机保存、导入或发现对方变化标记后立即发起下一轮；空闲每小时核对（可选两小时）。失败按 5 秒至 5 分钟退避。多网卡地址变化本身不计为数据变化。

只有内容是增量传输；清单每轮仍全量分页，并没有把全量清单宣称为严格 O(变化数) 的增量协议。并发双向会话不会制造重复版本，定期交换最终收敛。单条父分支数量上限 256，单次远端清单上限 100 万，标题 500 字、备注 32000 字；超限明确失败，保留现有数据。

授权每个请求重新检查；撤销后新会话和后续请求被拒绝。已经在途的字节和对方已经持有的数据不能撤回。

## 平台行为

Windows：WPF 主窗口关闭进入托盘，网络继续运行；从托盘退出时先异步停止网络、释放资料锁，再结束进程。按规范化资料目录建立互斥锁与当前用户命名管道，重复打开转交现有窗口。网络循环在线程池执行，避免退出等待 UI 上下文造成死锁。需要防火墙允许专用网络 TCP/UDP。尚无开机自启动或安装器。

Android：Activity 与 SyncService 共用进程级 AppRuntime，网络生命周期串行。服务声明 connectedDevice 前台类型，保持常驻通知、Wi-Fi MulticastLock；有长期配对设备时持有部分唤醒锁，用户关闭服务时释放。网络回调触发重新连接。Activity 离开时，服务仍在则保持网络；关闭后台服务但界面仍可见时，前台同步继续工作。前台服务本身不能绕过所有 Doze 限制，因此提供电池优化豁免申请入口，并说明小米后台策略。系统强制停止或回收后不承诺持续联网，不实现无限重启。参考 [前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types) 和 [Doze / App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby)。

当前构建 target SDK 36，最低 API 26。Android 17 对 target SDK 37 及以上应用要求运行时 `ACCESS_LOCAL_NETWORK`；未来升级 target SDK 时必须加入声明、解释和运行时申请，不能只改版本号。当前不把 SDK 37 支持记为通过。参考 [Android 本地网络权限](https://developer.android.com/privacy-and-security/local-network-permission)。

无互联网出口的路由器是目标支持场景，但没有物理设备实测；“同一 Wi-Fi”不等于“广播和 TCP 可互通”。AP 隔离、不同 VLAN、VPN、多网卡的优先路由都可能影响发现。本版本不自动修改系统网络或防火墙设置。

## 成员发现与自动同步

每个成员运行独立连接循环，优先尝试局域网发现地址，再尝试已配置地址和其他成员传来的地址。地址仅是未受信任的路由提示，TLS 必须匹配设备证书指纹。`space-hello` 在数据交换前合并同根签名成员日志，并交换可达地址；新成员无需与每个旧成员分别配对。

`done` 返回拍摄清单快照前的变化标记。`watch` 最长等待十秒，与本地变更事件竞速；修改取消空闲等待，下一轮先核对版本。对离线成员独立退避，手动同步或成员变化唤醒重试。空闲不反复交换完整任务清单，版本清单在实际核对时仍是全量分页。

转发保留原始 revision ID、actor 和附件哈希。NAS 复用同一 Core 空间与数据协议，是可选的持久副本。一个成员确认不等于全部设备确认；系统休眠、Android 后台限制、NAT 或网络隔离可能造成待同步。没有公共发现服务、打洞服务器或自动公网映射。

移除事件随成员日志传递。已移除身份只允许收到同根成员决定，不允许继续读取或上传任务。成员离线期间无法即时获知决定；已经传出的内容不能远程撤回。新邀请可以明确重新接纳同一身份。

## 便携位置与启动

Windows 默认数据库为 `AppContext.BaseDirectory/LanTodo.sqlite`。自定义位置的 `LanTodo.location` 放在程序旁，尽量保存相对路径；目标不可用时失败关闭，不创建空替代库。显式 `--data-dir` 优先，测试不会读取真实用户的旧目录。

迁移暂停网络和编辑，拒绝源目录、互相包含的目录、已有LanTodo数据和重解析目标。使用 SQLite 在线备份复制全部页面，检查记录及元数据，再持久化新位置，关闭旧连接并删除旧文件，接管新连接。窗口继续使用原运行时对象，桌面单实例锁切换到新目录。失败恢复旧位置设置和旧连接。崩溃若发生在新位置落盘后、原库删除前，可能留下完整旧副本，但不会丢掉新库。

已完成批量删除只处理用户确认的版本；有新编辑则跳过。所有实际删除在同一事务中写入墓碑，不物理移除历史。

Android 的 Activity 与 Service 共享异步初始化任务。Android 12 起保留系统 SplashScreen 到主页完成布局；更早系统显示居中标志。删除额外的临时文字页面，避免左侧文字闪现。完整就绪用 ReportFullyDrawn 记录，区别于首帧时间。

## v1.0.1 附件与管理页

附件元数据写入历史，原件独立存储，不同步数据库文件。空附件字段不参与序列化，保留旧消息哈希。服务只处理已授权设备对已引用附件的请求；完整校验成功前文件为 `.part`，不会展示为可用原件。新客户端需共同升级方可交换带附件的历史。

NAS 管理页在独立 HTTP 端口使用高熵 Bearer 管理令牌；本地命名管道仍只允许同一 OS 用户。管理令牌与配对码分离，HTML/JS/CSS 随服务嵌入，不依赖外部 CDN。授权码历史不保存秘密，重启后未使用码作废；删除历史记录不撤销已配对设备。详细审查见 [同步检查](sync-review-v1.0.1.md)。

## 网络空间与统一内容（v1.0.1 当前构建）

AppRuntime 保持一个统一 TodoStore，各 PeerNode 共用全部清单、回收站、版本历史和附件。每组网络成员、授权根、路由和邀请仍单独保存在 spaces 的连接数据库中；ConnectionProfile 显式区分连接配置和内容存储。唯一 TCP 入口按空间根路由，分别验证成员权限。内容更新会唤醒所有网络，具有多个成员资格的设备接力转发；内容共享不会合并不同网络的成员权限。

旧版各空间的历史先按不可变版本标识幂等合并，保留冲突、删除与失效记录，再校验并复制原件到统一 attachments。所有导入和原件复制完成后，才清理已迁移的来源记录；错误时来源仍可重试。复制不改变字节，重名使用序号。连接配置仍各自保留，备份只导出一份统一内容。

删除网络空间仅签名退出并持久化网络删除标记，继续保留全部内容与必要的退出证明；不会关闭其他网络或清空资料。最后一个网络移除后创建本机默认连接配置，内容仍可继续编辑。旧版用于删除内容的标记升级为网络退役标记，避免误清除统一清单。

原件按名称平铺于 attachments，附件索引以原子替换文件保存名称映射、已收到引用及不可复活的失效引用。可选 Instance 和 Purged 字段不改变旧版本哈希；失效状态先于原件传输交换，接收分块前再次检查本地删除。
