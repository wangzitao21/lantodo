# LanTodo 轻量化与可靠性修订 · build 17

日期：2026-09-11。保留 v1.0.1 展示版本、现有配色与功能；Android 安装序号递增至 17。

## 已落实

| 范围 | 现在的行为 |
| --- | --- |
| 恢复可靠性 | 先完整校验备份原件，再以同一 SQLite 事务提交历史与附件失效状态。损坏 ZIP、缺失原件、SQL 写入失败不会提前改变现有失效状态。本机无关的待下载原件不阻止恢复。 |
| 文件完整性 | 导出备份与上传原件前校验 SHA-256，缓存文件长度和修改时间避免逐块重复哈希；可靠备份可以修复同大小损坏的本地副本。读取失败、目录暂不可用、文件损坏与明确文件删除分开处理。 |
| 文件清理 | 当前版本的附件引用建立索引，只清理失去引用的原件；占用文件延后重试，不把已经提交的删除误报为失败。清理详情可在同步状态中查看。 |
| 数据读取 | 缓存当前列表，按记录索引历史、按引用索引附件；普通文本保存不再遍历所有历史附件或重复写删除索引。同日期内容按创建时间排序。 |
| Windows 列表 | 系统虚拟列表与容器回收；保持现有卡片、颜色、星标、附件、右键与冲突操作。更新相同记录时保留无变化的卡片。 |
| Android 列表 | 改用系统 ListView，按需生成可见卡片，保留滑动删除、长按菜单、图片/语音、来源和列表位置。 |
| 搜索与输入 | 搜索标题、备注和文件名，多关键词共同匹配，可组合分类与日期；Windows Ctrl+F，Enter 发送、Shift+Enter 换行；Android 使用日期/时间选择器。 |
| 草稿 | 两端快捷输入与详情草稿保存本机，文字停止输入约 500ms 后保存，附件选择立即保存。发送与清除对应草稿在同一事务提交。旧草稿遇到远端修改时另存为新想法。待发原件受草稿保护，移除未发送附件会清理无引用原件。 |
| 删除 | 移到回收站后提供 12 秒撤销，撤销使用版本检查。清空回收站以一次事务完成，跳过确认后发生变化的记录。 |
| 同步连接 | 空闲 watch 复用 TCP/TLS 与空间认证，继续保留旧版不支持 KeepAlive 时的兼容路径；发现缓存定期过期，避免 128 个过期发现项堵住新发现。 |
| 同步反馈 | 区分仅本机保存、等待上线、同步中、已同步设备数和待上线设备数；提供最近成功时间及错误信息，避免把离线设备算作已同步。 |
| Android 网络与电量 | 观察所有可用网络，支持无互联网的本地 Wi-Fi；显式移动数据开关，切换网络策略时先关闭旧连接。前台 30 秒发现/巡检，后台 120 秒；后台每轮约 15 秒持有多播锁，不持续持有 CPU 唤醒锁。 |
| NAS 管理 | 首次启动即要求令牌；未配置时在数据目录生成随机 admin-token，日志只给出文件路径。沿用已有令牌和会话密钥，浏览器会话期限为 14 天。 |

## 兼容与边界

- SQLite schema 与 ZIP 备份格式仍为 v1；新草稿和附件失效事务状态使用数据库 metadata。继续保留附件索引 JSON 以兼容已有目录结构。
- 草稿只保存在本机，不参与同步或 ZIP 清单备份。已发送内容照常自动同步。
- “彻底删除”移除清单展示与无人引用的原件，但保留含原文字的版本历史用于同步；没有新增隐私擦除或历史压缩协议。
- 本轮没有改成 Merkle 树、增量检查点或压缩历史协议。大规模历史的全量核对成本仍需后续独立优化；当前改动优先保持既有同步语义和兼容性。
- 自动同步依赖设备间可达路径；没有新增公网中继、NAT 穿透、iOS 或 macOS 客户端。
- Android 深度休眠和厂商后台策略仍可能延迟连接。模拟器不能替代真机 Wi-Fi/移动网络切换、锁屏与耗电测试，因此没有声称具体节电百分比。
