# 手机快速打开与重连 · build 18

日期：2026-09-12。展示版本仍为 v1.0.1，Android 安装序号为 18，沿用原发布签名。

## 原因与修改

旧版 Activity 先显示图标，等待完整 AppRuntime 和首页资料就绪才显示主界面、启动网络。打开后马上关闭，可能尚未开始连接。灰点还受真实设备认证状态影响，不能用“手机有网络”代替同步成功。

- 先构建可输入的首页，取消图标等待和退出动画；数据库、身份与网络初始化在后台进行，完成后绑定已有输入区，不替换焦点或新输入。
- 初始化期间发送的文字先通过独立文件持久保存，之后写入 SQLite 并触发同步。每条记录有稳定 ID，重启重放检查完整历史，防止重复或复活已经删除的记录。写入失败保留待发送条目。
- 草稿保留轻量文字镜像；载入时需要保留的旧草稿分别存放，恢复时与当前输入交换。重复恢复不会覆盖另一份较新的输入。
- 打开/回到 Android 或 Windows 前台、网络地址变化、手动同步均主动重连。每个成员最多三个地址错峰尝试，间隔 150ms，首个通过 TLS 身份检查的连接继续；发现新地址可取消旧握手，避免等待原先每个地址的 12 秒超时。
- 先上传本机更新，再下载远端历史；自动同步在附件分块之间发现新版本时优先开始下一轮文字同步，附件随后断点续传。单次显式 SyncAsync 仍完成附件传输。
- Android Release 使用 partial trimming 和 profiled AOT，并保留应用/Core 的反射序列化类型及回调。列表刷新先检查变化计数，避免无变化时扫描历史与附件；启动继续验证每条记录哈希和完整父图，去掉重复的第二次哈希计算。
- 开启后台同步时，发送后提供最长 15 秒的部分 CPU 唤醒锁，确认同步后提前释放；服务提前登记运行状态，避免界面已经离开而初始化才完成时关闭网络。

## 实测

Windows 宿主机上的隔离 Android 15 / API 35、x64 模拟器；使用正式签名 APK 覆盖升级，保留约 26～29 条既有测试记录、星标、颜色与语音附件。冷启动使用 am force-stop 后 am start -W，按系统首帧与 Fully drawn 日志记录；新版 Fully drawn 表示首页输入区可用，历史清单继续载入。

| 项目 | 结果 |
| --- | --- |
| build 17 首帧 | 约 0.9～1.0 秒，此时仍是图标等待 |
| build 17 主界面 | 2.939 秒（一次完整基线） |
| build 18 主界面 | 三次为 0.906、0.871、0.893 秒；中位数 0.893 秒 |
| 回到前台 | 一次明确 HOT 启动为 0.121 秒 |
| 初始化期间发送并立即强停 | 独立持久保存耗时 78ms；强停时没有 DataReady 日志，重开后成功重放，另一端只出现一条记录 |
| 初始化期间发送并立即返回桌面 | 独立持久保存耗时 111ms，后台完成初始化，宿主机配对终端约 2.31 秒后收到记录 |
| 旧 TLS 地址卡住时改走可用地址 | 核心回归实测 266ms |
| 前台触发重连打断旧握手 | 核心回归实测 124ms |
| APK 大小 | 从约 44.4 MB 缩至约 17.0 MB（十进制） |

这些是有限次数的模拟器及本机回环测试，不是所有手机、网络的速度保证。没有真实 Android 手机连接到当前工作环境，因此未给出真机锁屏、厂商后台回收或耗电结论。
