# 终端响应与启动优化 · build 19

日期：2026-09-12。展示版本仍为 **v1.0.1**，Android 安装序号为 **19**，沿用原发布签名。

本轮按个人长期使用的目标，集中改善手机打开、日常操作与收到同步更新后的显示速度。保留现有历史、数据库、备份与同步格式。

## 已实现

- **Android 卡片复用**：ListView 复用已有卡片及字体，不在每次滚动与刷新时重建全部子控件；内容未变化时跳过绑定，附件未变化时保留图片及播放控件。事件读取当前绑定记录，复用时重置滑动状态，并丢弃旧滑动动画的删除回调。
- **后台顺序保存**：完成、星标、颜色、删除及自动草稿保存从界面线程移至本地写入队列。队列内仅执行存储操作；单次失败不阻断后续任务，同一条记录尚在保存时限制重复操作。成功提示与撤销入口均在持久化成功后出现。
- **草稿边界保护**：发送、详情保存、正常退出和恢复草稿前等待旧队列完成，避免延迟草稿在发送后重新出现；修正发送清空输入与保存草稿的顺序。输入过程仍采用 500ms 合并保存，未承诺强杀发生在自动保存或生命周期回调之前时保住最后几个按键。
- **更及时的显示**：Android 内容变更合并等待从 80ms 改为 16ms；Windows 先检查变更计数和筛选条件，无变化时跳过全清单与附件遍历，保留定期附件状态核对。
- **启动减少重复工作**：Android 网络服务查询及枚举转到后台；附加空间仅在持久化身份字节相同时复制已打开证书句柄，避免重复密钥导入，不同身份继续独立加载。设备显示名称缓存随本机或远端昵称变化失效。Windows 设备和存储设置窗口按需创建。
- **同步路径精简**：去掉没有被使用的历史附件集合构造，当前附件引用与访问授权检查继续执行；保留上一轮的前台主动重连、文字优先传输、离线重试与附件断点续传。

## 对照测量

同一 Windows 宿主机、同一 Android 15 / API 35 x64 模拟器和约 29 条测试记录，先测原 build 18，再覆盖安装 build 19 候选包，各做三次 `am force-stop` 后冷启动。签名、既有配对和资料均保留。测量时未启用跨端回归中的新增测试记录。

| 指标 | build 18 三次（ms） | build 19 三次（ms） | 中位数变化 |
| --- | --- | --- | --- |
| 系统启动至输入区就绪报告 | 1094 / 1001 / 980 | 733 / 768 / 753 | 1001 → 753，缩短约 25% |
| OnCreate 至 ComposerReady | 771 / 708 / 715 | 533 / 518 / 524 | 715 → 524 |
| OnCreate 至 DataReady | 2267 / 2380 / 2298 | 1907 / 1911 / 1891 | 2298 → 1907，缩短约 17% |

系统计时与 OnCreate 内计时起点不同，不能混用。沿用旧包的报告位置作对照：系统 Fully drawn 在这里表示输入区就绪报告，**不代表完整历史列表已经显示**。DataReady 表示资料绑定和列表刷新已排队，也不是首批行绘制的精确时刻。16ms 是本程序设置的合并等待，不是承诺总响应时间或帧率。

build 19 新增阶段日志显示：主资料 StoreOpen 约 1.07–1.10 秒，IdentityAndSpace 约 0.41 秒；相同身份的第二个空间身份加载约 7–8ms。小资料集仍有运行时、序列化与数据库首次使用开销，后续应在实际手机上分阶段采样后再决定是否增加专用 AOT 配置。

本轮只有模拟器连接，未测真实手机的厂商后台回收、锁屏耗电或长时间温升。冷启动结果基于有限次数的同环境对照，不能保证所有手机都达到同一数值。
