# v1.0.1 统一空间与同步规则

所有设备加入同一个私有空间后自动互通。Windows、Android、Docker 使用同一套成员授权、历史合并和附件传输规则，NAS 是可选的常在线成员。

## 第一次使用

1. 任一设备打开“设备与同步 → 添加设备”，生成授权码和二维码。
2. 新设备打开“加入已有空间”，扫码或粘贴授权码，确认本机全部内容通过该网络同步。
3. 加入后，已有成员会自动收到新成员身份与地址提示，无需逐台配对。任何成员都可以继续邀请设备。

每个邀请五分钟有效，只能被一个设备身份兑换；同一设备可在有效期内重试中断的确认。重新生成、手动作废或重启会使未使用邀请失效。每台设备保留自己的密钥，授权码不是大家长期共用的密码。

## 修改会怎样流动

手机修改后先保存到本机，然后通知可连接的成员。电脑收到修改后，也能继续把它传给 NAS 或稍后上线的另一台电脑。转发保持原版本 ID、附件哈希和修改来源，相同内容不会因为多条路径而变成重复消息。

邀请设备不需要一直在线。只要其他设备能互相连接，就能继续同步。若 A 和 C 从不同时在线，B 可以先从 A 收到修改，再在 C 上线时传给 C。NAS 适合作为这样的常在线副本，但任何成员都能承担转发。

只有“在线且存在可达路径”才有即时同步。授权码负责加入空间，不负责打通 NAT：同一局域网会自动发现；跨网络可使用已有 VPN、可达域名 / IP 与同步端口。没有任何可用路径时，本机仍可编辑，等待下次连接。

修改立即触发核对；空闲时用变化通知等待新消息，定期完整核对用于补漏。每台设备独立连接和重试，一台不可达设备不会阻塞其他成员。界面上的“已同步”仅表示对应设备已经确认当前交换，不代表全部离线设备都已收到。

## 退出与移除

“移除”是空间范围的决定，会传播给所有成员；离线成员连接后收到。成员列表直接移除记录，不再保留“取消绑定 / 删除绑定”两套操作。内部保留签名的移除记录，阻止旧副本把成员恢复出来。

移除不会远程擦除对方已经收到的清单与附件。被移除设备停止通过该空间同步，仍可查看和编辑本机数据；使用新的有效邀请可以重新加入。退出空间也保留本机数据。加入另一空间无需退出：每台设备可保留最多 32 组可命名的网络连接，共用同一份清单与附件；移除与退出只作用于对应空间。

## 升级已有设备

保留数据，先把所有端更新到本次 v1.0.1 构建。已有旧版配对的设备不会自动把信任扩大到第三台设备。

选择一台设备点击“升级为统一空间”，再邀请其他设备依次加入。每台设备对目标空间只需加入一次。旧空间内容自动合并为统一清单，版本历史与原件保留。已使用统一空间的旧构建升级时原空间直接保留。旧授权码不能加入新空间，需重新生成授权码。

## 实现与边界

- 空间 ID 固定为创建记录的哈希；成员加入与移除采用设备私钥签名的因果日志，不共享管理员私钥。
- 传输继续使用固定证书身份的双向 TLS。每个请求检查当前成员权限；正在传输的字节和已保存数据不能远程撤回。
- 同一内容的并发修改仍保留为冲突，三端可以直接保留某个版本或删除；同步规则调整不丢弃历史。
- 当前面向个人空间：最多 64 个累计设备身份、512 条成员事件；达到容量时明确报错，不自动清除移除记录。频繁长期成员轮换需要后续设计安全的日志压缩。
- Android 受系统后台与电池限制；强制停止、电脑休眠、网络隔离时等待恢复。

验证范围见 [验证说明](acceptance.md)，Docker 部署见 [NAS 使用说明](nas.md)。

## 多空间与附件规则补充

一个设备身份可加入多个网络空间。每组连接单独保留授权根与路由，所有节点共享统一内容资料库。具有多组连接的设备接力传递内容；网络成员权限仍分别校验。删除连接不删除内容，备份只导出一份完整清单。

删除消息移入回收站；恢复和彻底清除都生成因果版本。永久清除不删除用于防止旧副本复活的版本历史。

附件原件按原名称平铺，哈希仍负责内容校验。每次主动上传有独立引用标识；原件在本地被删除后，已接收过的引用记为失效。同步先分页交换失效记录，再传输仍有效的附件，因此离线副本不能重新补回旧原件。主动重新上传同一内容形成新引用，旧引用继续失效。失效状态不等于远程擦除其他设备已保存的字节，其他成员只是将对应附件标为不可用。

所有端应更新到本次 v1.0.1 构建。新的附件引用字段和失效交换不适合与此前构建混用。旧版本 JSON 的序列化与哈希保持兼容。
